# Benchmark results

Generated by `benchmarks/run_benchmarks.py` on Linux-6.8.0-149-generic-x86_64-with-glibc2.35, Python 3.10.12.
**Every accuracy number below is a simulator result, not a hardware result.** The simulator and the diagnosis rules encode the same domain model, so §1-§4 measure *pipeline consistency* (alignment, baselining, decomposition and localisation under noise), not real-world accuracy. §1b and §1c are the parts designed to break that circularity. No hardware results exist yet; see the hardware validation plan in docs/methodology.md.

## 1b. Two concurrent faults, simulator (10 seeds per scenario)

Two faults on disjoint hosts with the same onset. The first-named fault is the slower bottleneck and sets the step time. *top-1 = bottleneck* asks whether the primary diagnosis names it; *secondary found* asks whether the masked fault is listed (primary or secondary suspect) with a correct culprit rank. Their features rise together, so the regression cannot tell from timing which one is the bottleneck: expect top-1 near chance and both found near 100%.
